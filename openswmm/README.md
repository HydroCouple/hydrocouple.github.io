# OpenSWMM browser workbench

This folder serves the website’s `/openswmm/` page. JavaScript module workers run the pinned OpenSWMM engine and the Qt-free MeshKit mesher on the local device. Asset URLs are relative to this folder. The site navigation and the return link to HydroCouple are the integration points.

## Use the workbench

The workbench opens with a welcome dialog on a first visit: bundled examples, **Open model files**, **New surface study** and **Couple a 1D network**. The first example, and the model shown on a first visit, is the Bellinge catchment in Odense (`examples/bellinge/`): the desktop GUI's coupled 1D/2D example with its 27,628-cell mesh and its own coordinate system, trimmed to the storm of 29 June 2012 (see its README). The four small decks beside it are quick tests. The **File** menu holds the same entries afterwards. The **Layers** panel on the left is organized as the desktop GUI's layer tree, in its order (the top of the tree is drawn last): **SWMM 2D Outputs** (water depth with its legend, flow streaks), **SWMM** (Nodes: junctions, outfalls, storage units, dividers; Links: conduits, pumps, orifices, weirs, outlets; Areas: subcatchments; Other: rain gages — each with the desktop's default symbol and its count), **Meshes** (mesh fill, mesh edges) and **Basemaps**. Only what the model has is listed. Each kind, group and category has a checkbox, each category an opacity slider, and the arrows move a category up or down (the basemap stays at the bottom); the inspector on the right lists the project and the last run; the strip below the map holds the run status and the result metrics, and the time bar (play, step, scrub the report frames) appears there once a run has surface results to play: after a model with a 2D surface finishes or a saved run with frames is reopened. It hides while a run is under way and for a model without results; a network-only model's results are in **Plot** and **View report**. The three toolbar toggles hide any of them. The side panels also collapse from the chevron in their header (the rail's **Layers** button reopens the layers panel) and resize by dragging their inner edge, with the arrow keys on a focused edge (Shift for larger steps, Home/End for the narrowest and widest) or back to the default width by double-clicking it. Which panels are open and how wide they are is remembered in the browser. Press `?` for the keyboard shortcuts (`⇧↵` runs the model, `⌘O` opens files, `Space` plays the frames).

The inspector's **Edit object** block edits the model through the engine itself: a second engine instance holds the deck open in a worker, the object lists and property rows come from the engine's API catalog (field paths, types, unit labels; defaults, refused values and enum members from `vendor/engine/catalog_defaults.json`), and every change is an engine call. **Undo** reverts the last change; **Apply to model** asks the engine to write the deck, which replaces the project's input and is what the next run uses. **Run model** applies edits not yet applied before it starts (and does not start when they cannot be applied, saying why); **Resume run** continues the model it saved, so it asks for them to be applied or undone first. **Simulation options** lists every `[OPTIONS]` key the engine holds (dates, steps, routing, tolerances, FV and quality switches) with dropdowns for the keys that have fixed vocabularies; the engine validates each value as it is set. `[2D_OPTIONS]` keys are not reachable through the engine API yet and stay in **Edit INP**. Clicking a surface cell on the map selects it in the editor: Manning's n, initial depth and tag can be changed per cell or applied to every cell at once. **Edit INP** still edits the text directly for sections the catalog does not reach. Only one engine instance holds memory at a time: the editing instance is dropped when a run, a mesh build or the hydrograph reader starts, and reopened from the project when they finish, so a large model costs one copy, not two.

**Time series**, **Curves** and **Time patterns** in the same list show a card per record: its extent, a preview, the objects that use it, its name (renaming updates every reference) and **New** / **Delete**. A delete first lists the references the engine will clear; **Undo** brings the record and its references back. **Edit values…** opens the record's table with a chart: dated rows take a date and a time of day on the model's clock (no time zone applies), elapsed-time rows count from the simulation start, a curve's columns are named for its type in the model's units, and a pattern has one factor per month, weekday or hour. Rows can be added, removed or pasted from a spreadsheet or a deck. **Save to model** hands the rows to the engine, which validates them (times and x values must increase) before the change is kept. A time series that reads a `FILE` is edited in its file.

**Control rules** opens the model's rule program as text; the engine checks each rule against the model's objects as it is typed and again when it is saved (comments in rules are not kept). A node's or link's properties end with the rules that name it. A node's card also lists its inflows, and **Edit inflows…** edits them in one dialog: external inflows (a time series with its conversion and scale factors, plus a baseline and its pattern, for flow or a pollutant as a concentration or a mass flow), dry-weather inflows (an average value and the monthly, daily, hourly and weekend patterns) and RDII (a unit hydrograph and the sewershed area). The rows are checked against the model's names and pattern types before the engine gets them, and an edited row keeps its place in the deck. **Unit hydrographs** are records like time series: a rain gage and, for all months or one month, the R, T, K and initial abstraction of the short, medium and long term responses, with a preview of the hydrograph; renaming one updates the nodes that use it.

**Pollutants** and **Land uses** are records too. A pollutant's card holds its properties (units, decay, concentrations in rain, groundwater, RDII and dry-weather flow), its co-pollutant and fraction, and the land uses, subcatchments and nodes that use it; a land use's card holds street sweeping, and **Edit buildup and washoff…** sets the buildup function (power, exponential, saturation or an external time series, normalized by area or curb length) and the washoff function (exponential, rating curve or event mean concentration, with cleaning and BMP efficiencies) for each pollutant. A subcatchment's card ends with its land use coverages and **Edit land uses and loadings…**: the percent of the subcatchment each land use covers (at most 100 in total) and the initial buildup of each pollutant. A node's card lists its treatment expressions, and **Edit treatment…** checks each one as it is typed: the engine checks the expression's syntax, and the workbench checks that every pollutant it names, and every `R_` or `C_` reference, exists. Renaming a pollutant or land use updates every row that names it; a delete lists them first.

**Climate and model settings** starts with a climate card; **Edit climate…** sets the air temperature source (none or a time series; a climate file the deck names is kept, not chosen here), evaporation (constant, monthly, a time series, or from temperatures or the climate file, with a soil recovery pattern and dry periods only), monthly wind speeds, the snowmelt parameters, the areal depletion curves and the monthly adjustments (temperature and evaporation added, rainfall and soil conductivity multiplied). Per-subcatchment adjustment patterns stay in **Edit INP**. **Transects** are records with a cross-section preview: Manning's n of the overbanks and the channel, the bank stations, the meander and station factors and the elevation offset, and the station and elevation points (pasted from a spreadsheet or from GR rows), which run from left to right and need some depth. A transect that links use keeps its name for now, and deleting one turns those links' cross-sections circular. **LID controls** are records too: a control's type sets its layers (surface, pavement, soil, storage, underdrain, drainage mat) and its underdrain removals, and a control in use keeps its type. A subcatchment's card lists the LID controls placed on it, and **Edit LID usage…** edits the placements: the number and size of the units, their initial saturation, the impervious and pervious area they treat, whether their outflow returns to the pervious area and where the underdrain goes. As in legacy SWMM, the units fit in the subcatchment and treat at most all of its impervious and pervious area.

**Selecting on the map.** The map tools above the zoom buttons select model objects. **Select** picks the node, link, subcatchment, rain gage or 2D cell under a click (a drag still pans); **Box** and **Lasso** take every visible node, link, subcatchment and rain gage inside a dragged rectangle or outline (2D cells are picked one at a time). Shift adds to the selection, Ctrl or ⌘ toggles, Alt removes and Esc clears. The selection is one model the views share: the map highlights it, the line at the top left of the map names it, Edit object shows the object picked last, and choosing an object in Edit object selects it on the map.

**Adding to the model on the map.** **Add objects** (the last map tool) lists what can be placed, each with its map symbol: junctions, outfalls, flow dividers, storage units and virtual junctions; conduits, pumps, orifices, weirs and outlets; rain gages. A click places a node or a rain gage; a click on a conduit inserts the node there instead, splitting the conduit in two (`C2` ends at the new node and `C2_B` carries on), as the desktop does. Outfalls end a network, so they are only placed on a free spot; a virtual junction is only inserted on a conduit and keeps its two pieces as one pipe (it is drawn with a dotted ring, and links cannot end at it). A link starts on a node, a click on a free spot adds a bend, a click on another node ends it, and the next link starts there; Backspace or a right-click drops the last bend and Esc stops (a second Esc leaves the tool). A drag still pans the map and the wheel zooms. New objects take the desktop's names (J, O, D, S, VJ, C, Pu, Or, W, Ou, RG and the first free number) and its creation values for the model's units (a 1 ft or 0.3 m circular conduit with n 0.013, a 15 ft or 4.5 m storage unit with 1000 ft² or 100 m² of area, a side orifice, a transverse weir, a functional outlet, an ideal pump that starts on, a 15-minute intensity gage), and a traced conduit's length is its length on the map: on the globe when the model is placed, else in the deck's `[MAP]` units (the model's own units when it names none). A flow divider diverts into the first link drawn out of it; **Apply to model** waits until every divider has one, since SWMM refuses a deck without it. A **subcatchment** is drawn corner by corner (a double-click or Enter closes it, Backspace drops a corner); its area is measured from the outline (acres or hectares), it takes the desktop's creation values and the infiltration parameters of the model's INFILTRATION option, and its rain gage and outlet start as the nearest gage and node, which its card shows first as **Rain gage** and **Outlet** (a node or another subcatchment). A node placed over a 2D surface takes the ground under it as its invert, as the desktop's terrain assistance does. **Move** (beside Add) drags a node or rain gage; the conduits that end at a moved node take their new length on the map. **Edit vertices** works on the link clicked: drag a vertex, right-click the line to add one, right-click a vertex to remove it; a conduit's length follows. **Map labels** (the deck's `[LABELS]`) are drawn on the map under Other in the layer tree; **Map label** in the Add palette places one where you click (its text, size, bold, italic) or, clicked on a label, changes or deletes it, and Move drags labels too. **Inlet junction** in the Add palette inserts an inlet junction on a STREET conduit: a dialog takes the inlet design, the node that receives what it captures (the nearest first; not the conduit's own ends or a virtual junction) and its placement (automatic, on grade, on sag); the conduit splits around it, the junction is drawn as a filled diamond with a dashed line to its capture node, and undo fuses the conduit back. **Convert to** on a node's or link's card changes its type (and that of the other selected objects of its kind) after a preview of what converts, what already is that type and what the engine refuses; the common values stay, values only the old type had are cleared, and undo brings the type back. With network objects selected, Delete (or Backspace) deletes them after listing what goes with them (the links that end at a deleted node) and the references that are cleared. Every map edit is one step of **Undo**, and the map always shows the editing model: objects appear where they were drawn, and nothing moves. **Run model** applies them first. The editing engine is also dropped while a mesh build, the hydrograph reader or a plot or profile read holds the memory, and edits not yet applied then go with it: apply them first.

**Plots.** **Plot** (below the map) opens the time series panel and adds the selected objects; in the panel, **Add selection as** adds them as any variable of their kind (node depth, head, volume, inflows, flooding; link flow, depth, velocity, volume, capacity; subcatchment runoff, rainfall, infiltration, evaporation, snow and groundwater; a 2D cell's depth and speed) or adds a system series. Each variable gets its own chart row on a shared time axis (never two y-axes), up to eight series in all, each keeping its color. A crosshair lists every series at the time under the pointer (the arrow keys move it on a focused chart), the time bar's current time is marked, and a click on a chart moves the time bar there. **Table** shows the values, **CSV** and **PNG** export them, and the panel resizes from its top edge. Network and system series are read from the run's binary output (for the objects the model reports) while the editing engine waits; 2D cells come from the frames in memory.

**Profiles.** **Profile** (below the map) opens a pipe profile along the selected nodes: the shortest path by length through them in the order they were selected (or a selected link's ends), drawn with the ground through the nodes' rims, the pipes from their offsets (LINK_OFFSETS depth or elevation) and openings, the water in them up to the hydraulic grade line or the crown, the HGL at the shown time and its maximum (dashed); nodes where the HGL rises above the rim are marked in amber. Heads are read from the run's binary output while the editing engine waits. With no nodes selected on a model with a 2D surface, **Profile** (or the **Profile line** map tool) draws a terrain profile instead: click along a line, double-click or Enter ends it, Esc cancels; it shows the bed from the mesh's vertex elevations, the water and its surface at the shown time and the maximum surface over the run (depths vertex-averaged, as the contours are). Each profile is a tab of the bottom panel beside **Time series**, with a crosshair that marks the place on the map, a table, CSV and PNG; the path or line is drawn on the map while its tab is shown. Profiles follow the time bar when the run has 2D frames; a network-only run's profile has its own time slider and opens at the time the path holds the most water.

**Water depth style.** **Style…** on the Water depth layer sets how depths are drawn. **Display** draws filled contours (the default) or colors each cell; filled contours: the cells' depths are averaged to the mesh vertices and each triangle is cut into bands between class breaks. **Classes** are a continuous ramp (the default) or equal intervals, quantiles, natural breaks or a list of breaks; the **color ramp** is Blues (the default), Viridis, Cividis, Magma, Inferno or Plasma, optionally inverted, stretched over each frame's range, the whole run's or a fixed range. **Contour lines** follow a number of levels or an interval from a base, with every Nth an index line and optional labels. The legend lists the classes, and the style is remembered in this browser. Depths are in meters. As in the desktop GUI, water no deeper than the model's `[2D_OPTIONS] DRY_DEPTH` (the engine's 0.001 m when the deck has none) is not drawn in any display, and the streaks keep to the water shown. **Hide water no deeper than** raises that threshold for display only (the desktop's thin-film depth): thin films stay in the model and its results but are not drawn. By default the depth is drawn as filled contours with water no deeper than 0.05 m hidden; the threshold returns to 0.05 m when another model opens, and a blank field means the model's own DRY_DEPTH. The **Mesh fill** layer still shades every cell.

**Layer symbols.** **Style…** on each SWMM kind's row and on the two mesh rows sets how it is drawn, as the desktop's per-kind symbol does: a node kind's or rain gage's marker (circle, square, triangle, diamond, star or cross; size, fill, outline), a link kind's line (color, width) and its flow-direction arrow (halfway along each link, pointing from its inlet node to its outlet node; on for every link kind as in the desktop, left off links shorter on screen than twice the arrow), the subcatchment area (fill, fill opacity, outline), and ID labels beside markers, along links or inside areas (a label that would overlap one already drawn is left out). **Mesh fill** is one color or the bed elevation on a ramp (the desktop's Terrain Fill; Terrain, Viridis, Cividis, Magma, Inferno, Plasma or Blues); **Mesh edges** take a color, an opacity and a width. Changes show at once on the map, in the 3D view (colors, sizes, shapes and widths) and in the layer swatches and the Add palette; **Reset** brings back the default symbol. Symbols are remembered in this browser. Coloring by an attribute or a result is planned with the 1D results styling.

**Basemaps.** **Add basemap…** under Basemaps shows each choice as a preview of the model's area. A Mapbox style (Outdoors, Streets, Light, Dark, Satellite Streets) is the bottom of the stack and choosing another replaces it; imagery and maps (Mapbox Satellite, OpenStreetMap, Esri World Imagery) and custom `{z}/{x}/{y}` tile layers (the server must allow cross-origin requests) stack above it, each with its own checkbox, order, opacity and remove button. Switching the Mapbox style off leaves the imagery alone. The stack is remembered in this browser. CARTO and Stadia, which the desktop lists, are left out: their tiles now need an account key (a keyed URL can be added as a custom layer).

**3D view.** With the basemap on, **3D view** (the cube under the selection tools) tilts the map and raises Mapbox's buildings; right-drag or Ctrl-drag rotates and tilts it, two fingers on a touch screen, and the compass below turns with the map (a click returns north up and flat). In the 3D view the model is drawn inside Mapbox's scene, in the layer tree's order and under the buildings, so a building hides the water and the network behind it: the meshes and the water depth (cells or filled contours) as WebGL layers on the ground, the network and the contour lines (labeled along the lines) as Mapbox layers. Flow streaks, the selection and the box and lasso stay on the map canvas above it. **3D buildings** in Basemaps switches the buildings; 3D view off returns the flat, north-up map.

**Aquifers** and **snowpacks** are records too. An aquifer holds the 12 parameters of the desktop's Aquifers dialog (soil, conductivity, evaporation with its optional monthly pattern, elevations and losses), checked as SWMM checks them (field capacity below porosity, the wilting point below field capacity, the water table not below the bottom, the initial moisture between the wilting point and porosity); subcatchments use it through their groundwater settings, and a rename carries their rows along. A snowpack holds the melt parameters of its plowable, impervious and pervious areas side by side and its snow removal, with the subcatchment that receives plowed snow. New ones start from values SWMM accepts (the engine's own start at zeros, which SWMM refuses). **Streets** and **inlets** (SWMM 5.2 street drainage) are records as well: a street is the cross-section STREET links use (distance to the crown, curb height, cross slope and Manning n, gutter depression and width, one or two sides, an optional backing), checked as SWMM reads it; an inlet design is a grate, curb opening, both together (a combination), a slotted drain, a drop grate or curb, or a custom capture curve, with the dimensions its type uses, checked as SWMM reads it and then by the engine. A street's or inlet's card lists the links and inlet placements that use it, and deleting an inlet removes its placements. **Events** (SWMM 5.2) list the periods a run is limited to, as dates and times on the model's clock, each starting before it ends.

**Object properties beyond the catalog rows.** Below a link's, node's or subcatchment's rows, cards hold what the engine's field catalog has no rows for: a link's **Cross-section** (the shape and the geometry it takes, an irregular channel's transect or a street conduit's street by name; orifices are circular or rectangular, weirs rectangular, triangular or trapezoidal), a conduit's **Losses**, an orifice's discharge coefficient and an outlet's coefficient, a pump's **Pump curve** by name; an **Outfall**'s type with its fixed stage, tidal curve or stage time series and the subcatchment its flow is routed onto; a **Storage** unit's shape (functional, tabular with its curve, cylindrical, conical, paraboloid, pyramidal) and exfiltration; a **Divider**'s type, diverted link, cutoff flow, diversion curve or weir; a subcatchment's **Infiltration** method and parameters and its **Groundwater** (aquifer, receiving node, flow coefficients and the custom lateral and deep flow expressions, which the engine checks) and **Frozen ground** (none or the model default `*` row, or ten SI values of its own); a conduit's **Inlet** (design, the node it sends what it captures to, number, clogging, flow restriction, local depression and placement; a design must fit the cross-section) and an inlet junction's; a storage unit's **LID** (a storage-node control, initial saturation and bottom) and, on a link with one such end, the **LID outlet** layer it is anchored to (undo puts the node's depth and the link's offsets back exactly); and the **Initial quality** of a node or link (a value per pollutant, plus water age and temperature when those options are on; blank leaves the model-wide value). Rows show for the type chosen; a change writes the whole card, checked as SWMM 5.2.4 checks it (a refusal shows under the card until it is put right), and is one Undo step. Three things still need the deck text (Edit INP), because the engine has no setter for them yet: a custom shape's curve, a subcatchment's subarea routing and an outlet's rating curve.

Edits through these editors mean the same as the same edits in the deck text: the engine writes the same deck and the run writes the same binary output.

Open a bundled example, an INP and its companion files, or a previously exported project ZIP. Select **Run model** to create local native reports and binary outputs. A running model can be **paused** and resumed between report steps; **Stop job** ends it at the next report step and keeps the report and outputs written so far (a second press, offered after eight seconds, kills the worker instead).

### Run controls

- **Stop at** (Run settings) ends a run at the first routing step at or past an elapsed time (hours:minutes or hours:minutes:seconds), with its outputs so far. Pausing and resuming leaves the results identical to an uninterrupted run.
- **Resume run** continues a stopped run from its saved state, with the same results as an uninterrupted run. A model without a 2D surface runs in an engine checkpoint session, so a stop (by hand or at Stop at) saves its state with the run's files. A model with a 2D surface stops without one: the engine does not yet take 2D surfaces into checkpoint sessions, and a hot start does not carry 2D depths. The engine also declines sessions for some other models (for example ones with water-quality pollutants it does not checkpoint, or evaporation from a time series or a climate file); those run normally without save/resume, and the status line gives the engine's reason when they stop.
- **Forcing** sets a rain intensity at a gage (replacing the gage's values) or an added inflow at a node, in the model's units. A run starts with the forcings set there; a change during a run takes effect at its next report sample, and rain reaches the surface at the gage's next interval. The inspector lists when the run took each one.
- **Scenarios** keeps snapshots of the model with the project: edit the model, then add it. **Run all scenarios** runs them in turn in one engine, with the current run settings and forcings (the same results, byte for byte, as running each one alone), then compares the surface balance, the deepest cell and the warnings, and overlays the same node depth or link flow from every run.
- The model's **warnings** count in the status bar during a run and are listed from the inspector afterwards (a run in a checkpoint session reads them from its report when it ends). **New surface study** builds a triangular domain with terrain and design forcing. The square domain can be replaced with a WGS84 GeoJSON Polygon with optional holes. A generated study has a geographic anchor. For small imported Cartesian models without a coordinate system, **Set map reference** assigns the southwest corner when the axes are east and north in metres.

### Coordinate systems

A model that names its coordinate reference system (`[OPTIONS] CRS`, as the desktop GUI writes it: an EPSG code such as `EPSG:25832`, or a WKT or PROJ definition) is placed on the globe by it, so its network, mesh and results sit at their real location when the basemap is on. The transform is proj4js with every projected and geographic EPSG system bundled as PROJ strings (`vendor/epsg/`, from the EPSG Geodetic Parameter Dataset), so it works offline and asks no service. The inspector's **Coordinates** line names the system; a code outside the table, or a definition the library cannot use, leaves the model in local coordinates and says why in the Layers panel. The CRS is edited like any other option in **Simulation options**.

**Connect a 1D network** takes a metric network with the same XY and vertical reference and a manually reviewed cell/node exchange. The network clock and selected direct-rain policy control the combined deck. Use **Edit INP** to configure more exchanges or advanced engine options. Preconfigured US-unit models can run directly. Independent solver mode runs eligible split-water configurations using separate network and surface handles and the engine’s synchronous exchange callback.

The depth layer and streaks use live, paired velocity components at the displayed time; streaks move at a fixed speed on screen, scaled to the frame's flow speeds, so they read on any mesh size. Each streak is drawn as in the desktop GUI: a teardrop with a round head and a tail that thins and fades, white with a thin dark edge, fading in and out over its few seconds of life. Project ZIPs preserve all project inputs, run-directory outputs and preview arrays. IndexedDB retains the latest successful workspace for this origin. At startup the welcome screen opens nothing until a choice: **Continue** (or Esc) reopens that workspace, or pick an example or open files; with **Show at startup** off it reopens at once. A new version of the workbench takes over on the next reload, or from **Update ready** in the header while a project is open. **Export project** creates the user-owned portable copy. After the service worker finishes installing, the app, examples and saved project layers work offline.

### Terrain and storms

The study form's **Mesh** block takes optional constraint lines (a GeoJSON file of LineString or MultiLineString features inside the domain, which become mesh edges), the minimum triangle angle (0–34°, default 30), smoothing passes, a minimum cell size and the strict-sizing switch; MeshKit refuses a mesh with unresolved size conflicts while strict sizing is on. The generated project carries `mesh-report.json` with MeshKit's counters (constraint audit, size and transition conflicts, inserted vertices, resolved options), and the status line summarizes it.

All elevation sources are read directly by the browser. Terrain is sampled bilinearly onto a regular grid of up to 33 × 33 nodes. The requested area uses a local metric approximation with a maximum 5 km span. The files panel and project ZIP include the raw provider response and the derived elevation grid. Dropped connections, HTTP 429 and 5xx responses are retried twice.

- **USGS 3DEP** (U.S.) requests one Float32 GeoTIFF from the [3DEP ImageServer `exportImage`](https://elevation.nationalmap.gov/arcgis/rest/services/3DEPElevation/ImageServer) at 1/8 of the node spacing, between 1 m and 1/3 arc-second, and samples it using the returned georeference. The service may report sea surface as 0 m. Areas without data stop the study.
- **AWS Terrain Tiles** (global, no account) download the 1-arc-second Skadi HGT tile for each 1° cell (13–16 MB each) from the [AWS Open Data terrain tiles](https://registry.opendata.aws/terrain-tiles/). This is a mosaic built from SRTM, USGS 3DEP and national elevation models, not the NASA SRTMGL1 product. The attribution text required by Mapzen is in `licenses/Terrain-Tiles-attribution.txt`.
- **OpenTopography** fetches NASA SRTMGL1, Copernicus GLO-30 or NASADEM clipped to the study as an ASCII grid through the [Global DEM API](https://portal.opentopography.org/apidocs/). Each user enters their own free API key. The browser keeps it in local storage for this site. It is sent only to OpenTopography and never written to the project, its files or its exports.
- **Local SRTMGL1 tiles** accepts original `*.SRTMGL1.hgt.zip` files within approximately 56° S to 60° N.
- A **local JSON raster** has integer `rows` and `columns`, southwest `x` and `y` equal to zero, positive meter node spacings `dx` and `dy`, and a flat `heights` array in meters. Rows increase northward. An imported grid must cover the domain and have finite elevations. The synthetic plane supports offline demonstrations.

Enter the design depth, for example from the [NOAA Atlas 14 PFDS](https://hdsc.nws.noaa.gov/pfds/) for the study point. NOAA's servers do not permit browser requests from other sites, so the workbench does not look depths up itself. Select uniform, triangular, SCS I/IA/II/III, NRCS MSE3, or one of four Huff regional point-median patterns. SCS and MSE3 use their published 24-hour duration. The exported model and rainfall CSV contain the actual five-minute interval intensities.
- Tabulated distribution data and scaling follow the desktop Data Sources plugin, revision `769584f`. The source attribution is in `distributions.mjs` and the license is in `licenses/`. [Published method references](https://github.com/HydroCouple/hydrocouple.gui.data/blob/main/docs/rainfall-methods.md)

## Mapbox and GitHub Pages

Create a dedicated **public** Mapbox access token in the Mapbox account dashboard. Add the allowed URL `https://www.hydrocouple.org`, the origin named in the website’s CNAME. Enable public read scopes needed by the style, such as `styles:read` and `fonts:read`. Keep Mapbox attribution visible. Use a separate development token restricted to `http://localhost:8765` if needed. Add an alternate production origin only if it directly serves this application. The app uses a referrer policy that sends the origin on HTTPS cross-origin requests. [Mapbox token management](https://docs.mapbox.com/accounts/guides/tokens/)

GitHub Pages publishes the website's `master` branch as committed (**Settings → Pages → Build and deployment → Source → GitHub Actions**). The workflow `.github/workflows/pages.yml` builds and tests nothing: it writes the public token from the repository secret `MAPBOX_TOKEN` into `openswmm/config.json` (and into the offline cache version, so a changed token reaches cached copies) and deploys. The built runtimes in `openswmm/vendor/`, `openswmm/config.json` and `openswmm/offline-files.json` are committed with the source; commit `config.json` with an empty token (the bundler writes one when `MAPBOX_PUBLIC_TOKEN` is empty). `.nojekyll` at the site root serves every file as it is. Without the secret the app stays in local model view and the basemap is off. [GitHub Pages publishing sources](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

Every visitor can inspect a deployed public token; the secret only keeps it out of the repository. Never put an `sk.` token in the site. The bundler rejects secret-token inputs. ## Build and verify locally

Build the runtimes locally from the engine revision engine.wasm pins: its TypeScript wrappers and Emscripten module, and run `npm --prefix wasm run build` in MeshKit. The website bundler and tests need Node.js 22 or later. The bundler accepts local paths to the compiled packages and to unpacked JSZip 3.10.2, proj4 2.23.0 and epsg-index 2.0.0 packages (`npm pack <name>@<version>`). Set `MAPBOX_PUBLIC_TOKEN` in the shell if using the online basemap.

```sh
node openswmm/prepare.mjs --engine /path/to/openswmm.engine.wasm --mesh /path/to/MeshKit --jszip /path/to/jszip-package --proj4 /path/to/proj4-package --epsg /path/to/epsg-index-package
node --test openswmm/tests/model.test.mjs openswmm/tests/records.test.mjs openswmm/tests/crs.test.mjs openswmm/tests/layers.test.mjs openswmm/tests/panels.test.mjs openswmm/tests/timeline.test.mjs openswmm/tests/selection.test.mjs openswmm/tests/plots.test.mjs openswmm/tests/depth-style.test.mjs openswmm/tests/profiles.test.mjs openswmm/tests/streak-style.test.mjs openswmm/tests/objects.test.mjs openswmm/tests/editing.test.mjs openswmm/tests/properties.test.mjs openswmm/tests/symbol-style.test.mjs
node openswmm/tests/serve.mjs
node openswmm/tests/browser.mjs   # with the server running and Playwright installed in openswmm/tests
```

Open `http://localhost:8765/openswmm/`. Add `--simd /path/to/simd/dist` when a same-revision engine was compiled with `-msimd128` on both C and C++ targets, and `--threads /path/to/threads/dist` for the engine built with `-DOPENSWMM_WASM_THREADS=ON` (WebAssembly threads plus Emscripten's OpenMP runtime, so the engine's parallel solver loops use every core). Automatic selection tries the threaded module when the page is cross-origin isolated, then SIMD, then the portable solver. The actual backend appears in the header and saved run.

Threads need `SharedArrayBuffer`, which browsers grant only to cross-origin-isolated pages. GitHub Pages cannot send the `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` headers, so the service worker adds them to every same-origin response: the first visit runs single-threaded while the worker installs, every later load is isolated and the header shows the core count. Under `require-corp` every cross-origin load must use CORS; the basemap script and stylesheet are loaded with `crossorigin`, and terrain and tile requests already are CORS requests. The run sets `[OPTIONS] THREADS` to min(4, cores); the deck's own value is kept when no thread team is available. The team serves the 2D marcher's face and cell loops; the 1D FV solver's parallel regions are kept serial (`OPENSWMM_FV_OMP_MIN_*`) and the OpenMP workers do not spin between regions (`KMP_BLOCKTIME=0`), because WebAssembly's fork/join cost makes fine-grained regions and oversubscription slower than one thread. Measured on an M1 (2026-11-22, outputs bit-identical to the single-threaded build): a 20k-cell 2D study ran 2.2× faster with 4 threads; a 1D-FV-dominated model gained 1.2×.

A threads build configured with `-DOPENSWMM_WASM_WEBGPU=ON` also carries the WebGPU 2D marcher; `prepare.mjs` detects it and Run settings then offer **GPU · WebGPU 2D (experimental)** on isolated pages with WebGPU. It is never chosen automatically. For that run it sets `[2D_OPTIONS] BACKEND WEBGPU` (not saved into the model) and keeps the model's own scheme: local inertial, diffusive wave, or full shallow water at first or second order. It covers triangles and quadrilaterals, the FLAT and VFR cell closures, MEAN and VFR_FACE face depths, LTS_TIERS 1–8, every boundary type (wall, normal flow, stage and flow, constant or from a time series, and rating curve), rain, evaporation, infiltration and coupling-rate sources, and 1D–2D coupling through junctions and outfalls, the optional momentum physics (Coriolis, turbulence, wall drag) of an uncoupled full shallow water model, and transported pollutants, MSX species, water age and temperature (with dispersion, boundary quality and the junction exchange; aging, decay and reactions stay on the CPU, and coupled surface heat exchange runs on the CPU marcher); any other model stays on the CPU marcher and the report says why. The map's flow-streak animation pauses while any job runs, so its redraws do not compete with the solver. Dynamics run in 32-bit floats; water is booked in exact integer volume units, so the device's own balance closes to the unit and the reported continuity error is only the 32-bit rounding of the rain rate (about 2e-8). Measured on an M1 (2026-11-22/23, the study mesh refined to 80k and 320k cells, against the 4-thread CPU marcher on the same deck): about 2× faster at 80k cells and 3.5× at 320k cells with the FLAT closure, 4.3× at 80k cells with VFR, and 6.5–7× on 60k–70k-cell quadrilateral meshes with VFR; with full shallow water, 3.7× (first order) and 11× (second order) on the 80k-cell UK Environment Agency test 4, with the same step counts as the CPU marcher; at 20k cells the per-step synchronization costs about as much as the CPU saves. Momentum physics takes every step decision on the host (wave-limit trials, mixing sub-steps): 2–3× slower than the CPU marcher at 20k cells, 2.6× faster at 80k and 4.4× at 320k. Its mixing accepts a kinetic-energy rise below 1e-5 relative (1e-13 on the CPU), so its step schedule can differ slightly. Transported species are held in 32-bit floats: concentrations agree with the CPU marcher to about 1e-6 relative (1e-5 for water age) and each species' balance closes to between 5e-8 and 2e-5 of its largest term. Transport costs the CPU marcher 5–9× its water-only time and the WebGPU marcher little, so with species the WebGPU marcher is 3–20× faster even at 20k cells.

To publish, rerun the bundler with an empty `MAPBOX_PUBLIC_TOKEN`, run the tests and the browser test, and commit `openswmm/vendor/`, `config.json` and `offline-files.json` with the source; pushing `master` publishes the site. The same folder runs from any static file server.
